# System architecture (one page)

**What it is.** A self-hosted platform that lets a researcher configure a simulated laboratory procedure, get a second
person's approval for exactly what runs, execute it through a durable worker, and have an independent engine (OpenMHS,
pinned by commit and binary digest) judge the result. Evidence, verdicts and reports are stored with digests and can be
regenerated byte for byte.

```
 Researcher / engineer / viewer ──► Web app (Next.js) ──► API (FastAPI) ──┬─► PostgreSQL   metadata, jobs, audit
   dark and light, keyboard, axe-checked                  roles + workspace │
                                                          isolation (404)   ├─► content-addressed storage  evidence, reports, recordings
                                                                            │
   Agent (Strands harness, separate uv project) ◄── runs as the asker ──────┤   read-only typed tools; drafts only
        │  model = any OpenAI-compatible endpoint, key in the server's     │
        │  environment; per-session and daily spend caps; full trace       │
        ▼                                                                  ▼
   proposes ─► a person files it ─► a DIFFERENT engineer approves ─► durable worker ──► adapter SDK (W3C WoT / LabThings)
                                                                       lease, journal,        │
                                                                       safety check,          ├─► virtual laboratory: pump, balance,
                                                                       timeout, retry         │   simulation controls  (SIMULATED)
                                                                            │                 ├─► simulation hosts: Gazebo (real), self-test model
                                                                            ▼                 └─► ROS 2 observer: read-only, recorded graph
                                                                  OpenMHS engine (pinned) ─► verdict, contract, intervals
```

## The five rules the design enforces

1. **Commands go only to simulated environments** whose devices also report `simulated=true` (D-026). Physical equipment
   is discovered and read, never commanded. The platform is never in a robot's real-time or safety path.
2. **Two people.** Whoever requests or proposes a run is never the one who approves it. Studio experiments approve one
   exact checksum (D-037); workflow proposals refuse self-approval.
3. **The engine decides.** The platform computes no statistic. The instrument's own report (the pump says it dispensed
   50 µL) and the independent measurement (the balance) are kept apart and compared by the engine.
4. **The agent cannot act.** It reads through typed, allow-listed tools as the person who asked. It has no tool to approve,
   start, edit or command. At most it drafts a follow-up; a person files it, and a second person still approves it.
5. **Nothing is invented.** Faults change what physically happens in the simulation, never what a device reports.
   Simulated evidence carries its label everywhere; missing evidence is "unknown", never success.

## Data separation

Every record belongs to a workspace; another workspace's ids return 404 (tested over every route). Uploads and captures
are size-limited and checked against digests. The model key lives only in the server's environment; it is never sent to a
browser, stored, logged or put in a trace. Self-hosted: no evidence leaves the installation except what the operator's own
model endpoint receives in a session (tool results the asker could already read).

## What is real and what is simulated

Real: the API, worker, engine, storage, approvals, audit and the agent harness. Simulated: the pump and balance (a
LabThings virtual bench with a seeded noise model and injectable faults) and the self-test simulation host (a kinematic
model, not a simulator). Real simulation: headless Gazebo runs of the OpenAMRobot command-loss regression. No physical
hardware is connected.
